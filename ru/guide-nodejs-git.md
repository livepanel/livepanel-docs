# Деплой Node.js-приложения из GitHub

В этом руководстве подключим к панели приложение Express (или Next.js, NestJS) из GitHub: после каждого `git push` сайт обновляется сам.

**Понадобится:** репозиторий на GitHub и домен, направленный на сервер (например `api.example.uz`).

## 1. Подготовьте приложение

Панель запускает приложение через файл **`app.js`** в папке сайта и передаёт порт в переменной окружения `PORT`. В корне репозитория должен быть `app.js`:

```js
const express = require("express");
const app = express();

app.get("/", (req, res) => res.json({ ok: true }));

app.listen(Number(process.env.PORT), "127.0.0.1", () => {
  console.log("listening on", process.env.PORT);
});
```

Для **Next.js или NestJS** писать `app.js` самому не нужно: на шаге 2 создайте сайт через **CMS / Фреймворк → Node.js → Next.js** (или NestJS). Панель сама запишет `app.js`, который запускает приложение на нужном порту и адресе. Деплой из Git не удаляет файлы, которых нет в репозитории, поэтому этот файл останется и будет работать с кодом из репозитория.

Пакеты должны быть в `package.json`. Не добавляйте `node_modules` в репозиторий.

## 2. Создайте Node.js-сайт

1. **Сайты → «Создать сайт» → Node.js** (для Next.js и NestJS — **CMS / Фреймворк → Node.js → Next.js / NestJS**).
2. Домен: `api.example.uz`, нужная версия Node.js (другие версии — **Система → Приложения**).
3. **«Создать сайт»**.

## 3. Подключите репозиторий

![Git](../images/git.png)

1. Плитка **«Git»** на странице сайта.
2. **Адрес репозитория:**
   - публичный — `https://github.com/user/app.git`;
   - приватный — `git@github.com:user/app.git` и добавьте **ключ развёртывания** со страницы в GitHub: **Settings → Deploy keys**.
3. **Ветка:** `main`.
4. **Команда после развёртывания:**

   ```bash
   npm ci --omit=dev || npm install --omit=dev
   ```

   Если нужна сборка (Next.js, NestJS, TypeScript):

   ```bash
   npm ci && npm run build
   ```

5. **«Подключить и загрузить»** (для приватного — **«Развернуть»** после добавления ключа).

В логе деплоя видно каждый шаг; в конце служба сайта перезапускается. Подробнее — [Деплой из Git](git-deploy.md).

## 4. Переменные окружения

Не пишите секреты (адрес базы, API-ключи) в репозиторий. **Настройки → Бэкенд → Переменные окружения**:

```text
NODE_ENV=production
DATABASE_URL=mysql://app_user:parol@localhost:3306/app_db
JWT_SECRET=...
```

При сохранении приложение перезапускается. Нужна база — [Базы данных](databases.md).

## 5. Автоматический деплой при каждом push

1. Скопируйте **адрес вебхука** со страницы Git.
2. GitHub: **Settings → Webhooks → Add webhook** — Payload URL: адрес вебхука, Content type: `application/json`, **Just the push event**.
3. Если сертификат панели самоподписанный, отключите **SSL verification** или выдайте панели доверенный сертификат ([Адрес панели и SSL](panel-access.md)).

Теперь через несколько секунд после `git push origin main` сайт обновится; в логе видно, кто запустил деплой (**через вебхук**).

Из CI (GitHub Actions и других) деплой можно запустить и через [API](api-reference.md): `POST /api/v2/git` с `{"domain":"api.example.uz","action":"deploy"}` (тариф Premium).

## 6. SSL и проверка

1. **SSL-сертификаты → Let’s Encrypt** ([SSL-сертификаты](ssl.md)).
2. Откройте `https://api.example.uz`.

## Если что-то не так

| Признак | Что делать |
|---|---|
| Сайт отвечает **502** | Приложение не запустилось: **Логи → Лог приложения**. Чаще всего порт задан жёстко вместо `PORT` или нет `app.js` |
| Деплой «команда завершилась с ошибкой» | Конец лога деплоя — обычно ошибка `npm` или нет пакета |
| Деплой остановился через 20 минут | В команде есть бесконечная команда вроде `npm start` — уберите её |
| Изменения не видны | Зелёный ли вебхук в GitHub (**Recent Deliveries**) и верна ли ветка |
